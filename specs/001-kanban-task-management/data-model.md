# Data Model: Kanban Task Management

Phase 1 output. Entity definitions, relationships, validation rules, and state transitions
derived from the feature spec.

## Entities

### User

Predefined team member (exactly five seeded: one product manager, four engineers).

| Field | Type | Constraints |
|-------|------|-------------|
| Id | UUID (PK) | Required, generated |
| Name | string | Required, trimmed, 1–100 chars |
| Role | enum | Required; `ProductManager` or `Engineer` |
| CreatedAt | timestamp (UTC) | Required, set on seed |

- Invariants: exactly five `User` rows exist in phase 1 (FR-001).

### Project

Container for tasks. Three sample projects are seeded (FR-003).

| Field | Type | Constraints |
|-------|------|-------------|
| Id | UUID (PK) | Required, generated |
| Name | string | Required, trimmed, 1–120 chars; duplicates allowed |
| CreatedById | UUID (FK → User) | Required; the creator |
| CreatedAt | timestamp (UTC) | Required |

- Relationships: one `Project` has many `Task`.

### Task

Unit of work. Belongs to exactly one project and exactly one Kanban column (FR-006).

| Field | Type | Constraints |
|-------|------|-------------|
| Id | UUID (PK) | Required, generated |
| ProjectId | UUID (FK → Project) | Required |
| Title | string | Required, trimmed, 1–200 chars |
| Description | string? | Optional, trimmed, max 2000 chars |
| Status | enum | Required; `ToDo` \| `InProgress` \| `InReview` \| `Done`; new tasks = `ToDo` (FR-007) |
| AssigneeId | UUID? (FK → User) | Optional (unassigned allowed); must reference one of the five users |
| CreatedById | UUID (FK → User) | Required; author |
| CreatedAt | timestamp (UTC) | Required |
| UpdatedAt | timestamp (UTC) | Required, updated on any change |

- Relationships: one `Task` belongs to one `Project`; has many `Comment`; has optional one
  `Assignee`; has one `Creator`.

### Comment

Text note on a task (FR-010, FR-011).

| Field | Type | Constraints |
|-------|------|-------------|
| Id | UUID (PK) | Required, generated |
| TaskId | UUID (FK → Task) | Required |
| AuthorId | UUID (FK → User) | Required |
| Text | string | Required, trimmed, 1–2000 chars |
| CreatedAt | timestamp (UTC) | Required |

- Relationships: one `Comment` belongs to one `Task`; has one `Author`.

### Notification

In-app event record generated by the API (scope added by plan input).

| Field | Type | Constraints |
|-------|------|-------------|
| Id | UUID (PK) | Required, generated |
| UserId | UUID (FK → User) | Required; the recipient |
| Type | enum | Required; `TaskAssigned` \| `TaskStatusChanged` \| `TaskCommented` |
| Message | string | Required, human-readable, trimmed |
| TaskId | UUID? (FK → Task) | Optional; related task |
| ProjectId | UUID? (FK → Project) | Optional; related project |
| IsRead | bool | Required, default `false` |
| CreatedAt | timestamp (UTC) | Required |

- Relationships: one `Notification` belongs to one recipient `User`; optionally references a
  `Task` and/or `Project`.

### Kanban Column

Fixed ordered set (not a persisted entity — an enum/constant set), FR-006.

```
ToDo (1) → InProgress (2) → InReview (3) → Done (4)
```

## Relationships (summary)

```
User 1──N Project (creator)
User 1──N Task    (creator)
User 1──N Task    (assignee, optional)
User 1──N Comment (author)
User 1──N Notification (recipient)
Project 1──N Task
Task    1──N Comment
```

## State Transitions

`Task.Status` is the only stateful transition (FR-008). Movement is allowed between **any two**
columns, including backward (e.g., `Done` → `InProgress`), per the spec's edge case.

```
ToDo ⇄ InProgress ⇄ InReview ⇄ Done   (any pair; no forbidden transitions)
```

- Transition side effects (D10): the API emits a `TaskStatusChanged` notification to relevant
  recipients on a successful status change.

## Validation Rules (constitution Principle II — fail closed)

| Input | Rule |
|-------|------|
| Project.Name | Required; trimmed; 1–120 chars |
| Task.Title | Required; trimmed; 1–200 chars |
| Task.Description | Optional; trimmed; ≤ 2000 chars |
| Task.Status | Must be one of the four enum values |
| Task.AssigneeId | If present, must reference one of the five seeded users |
| Comment.Text | Required; trimmed; 1–2000 chars |
| User identity header | Must reference one of the five seeded users (reject otherwise) |

All inputs are trimmed before validation; empty/whitespace-only values are rejected with a
clear error (FR-012, SC-005).
